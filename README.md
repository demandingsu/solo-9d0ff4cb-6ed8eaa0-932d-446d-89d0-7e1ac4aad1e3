# 薪资成本中心勘误入账系统

Flask + SQLite 单页应用：开放月导入薪资单，封账后发现的成本中心/金额错误，
通过勘误在新开放月“冲回 + 重入账”，并按入账月导出 CSV。Docker Compose 一键启动。

## 快速开始

```bash
docker compose up --build
# http://localhost:8000
```

数据持久化在命名卷 `payroll-data` 的 `/data/payroll.db`。首次启动自动把当前月设为开放月。

不使用 Docker：

```bash
pip install -r requirements.txt
python -m payroll_app.app          # 或 gunicorn wsgi:app
```

## 数据模型

| 表 | 作用 |
| --- | --- |
| `months` | 每个 `YYYY-MM` 的开放/封账状态。封账不可逆（触发器强制）。 |
| `postings` | 入账流水，按 `entry_month` 出报表。金额带符号，冲回为负。 |
| `slips` | 每张薪资单当前生效的成本中心、金额与生效入账月。 |
| `adjustments` | 已处理勘误号 + 内容指纹，用于幂等与冲突检测。 |
| `slip_revisions` | 每次勘误引起的生效值变更（审计）。 |
| `wh_partitions` | 数仓镜像分区：载入代次 `load_seq`、行数、最近替换时间。 |
| `wh_postings` | 数仓流水镜像，列与月明细导出一致；`partition_month` 为实际落入月。 |
| `wh_previews` | 重装预览快照（组内分区、代次/内容指纹、错投边指纹、状态）。 |

`postings` 上有三个触发器：任何对已封月份明细的 INSERT / UPDATE / DELETE 直接 `RAISE(ABORT)`；
`months` 上有触发器禁止 `closed → open`。即使绕过应用层写库也会被拦截。

## 业务流程

**原始导入** `POST /import/originals`，CSV 表头 `薪资单号,成本中心,金额分`。

- 只能导入**开放**入账月；该批薪资单的“薪资所属月”即该入账月。
- 整份文件先做行级校验（表头、列数、单号唯一、金额为整数、成本中心字符集），
  有任何错误则一条都不写。
- 已存在的薪资单号不能再次导入，必须走勘误。

**提交勘误** `POST /import/adjustments`，CSV 表头 `勘误号,薪资单号,成本中心,金额分`。
目标入账月必须是开放月。按原单所属月状态分流：

| 原单所属月 | 处理 |
| --- | --- |
| 未封账 | **直接改原行**：更新该月 `original` 流水和 `slips` 的成本中心与金额，不新增流水，不改入账月。勘误必须提交到原单所属月。原行只保留最近一次勘误号，历次变更在 `slip_revisions` 可查。 |
| 已封账 | 在**本次开放入账月**写两条流水：`冲回`（上次生效中心，`-上次生效金额`）与 `重入账`（更正值）；两条都带原单号和**薪资所属月**。已封月流水一行不动。 |

因此：

- **封账先完成** → 勘误先落到新开放月（原月保持原样，新月的冲回+重入账表达更正）。
- **勘误先完成** → 当月明细已含更正（未封账时是原地修改），随后封账即固化该结果。

**幂等**：`adjustments.adjust_no` 主键。相同勘误号 + 相同内容（薪资单号、成本中心、金额）
再次提交 → `duplicate_skipped`，不产生任何新流水（换入账月重传也一样）；
相同勘误号 + 不同内容 → 整批拒绝，提示“已用不同内容处理过”。

**原子性**：原单导入与勘误批次都在 `BEGIN IMMEDIATE` 单事务内；
任一校验或写入失败整体 `ROLLBACK`，数据库保持调用前状态。

**导出** `GET /export/<YYYY-MM>.csv`：按入账月下载流水，含入账月、薪资单号、
薪资所属月、流水类型、成本中心、金额分、勘误号、修订号。

**页面**：`/` 月份管理与状态、两个导入表单、数仓镜像分区总览、当前生效薪资单、已处理勘误；
`/month/<YYYY-MM>` 该月本地明细与数仓镜像分区（上传 / 预览入口）。

## 数仓分区重装（错投流水双向追查）

薪资流水在数仓侧按“实际落入月（分区）”存放，可能因落错分区而错投。
系统在本地维护一份数仓镜像，支持上传分区、预览重装范围、确认后整组重装。

**上传分区**（月明细页入口）`POST /warehouse/upload`，CSV 表头沿用月明细导出的 8 列：
`入账月,薪资单号,薪资所属月,流水类型,成本中心,金额分,勘误号,修订号`
（流水类型接受 `原始/冲回/重入账`，也兼容英文 `original/reverse/rebook`）。
表单选择该文件**实际落入的月份**，上传即整体替换镜像中的对应分区（单事务，
失败保持原分区），分区载入代次 `load_seq` +1。无关分区可照常上传、互不影响。

**错投判定与双向追查**：镜像行的实际分区 `partition_month` 与行内“入账月”不一致即为错投；
以错投行为边，在分区间构建无向图（实际分区 ↔ 应入账月）。
`POST /warehouse/preview` 从任一分区出发做连通分量搜索，列出所有相连分区并冻结快照
（每分区载入代次、内容指纹、全组错投边指纹），在 `/warehouse/preview/<id>` 页面展示
组内分区、各自封账状态与全部错投流水。

**确认整组重装** `POST /warehouse/reload/<id>`：确认时在 `BEGIN IMMEDIATE` 单事务内
重新核对快照，全部通过后用每个分区**对应月份的已封账流水**（本地 `postings`）
一次替换整组镜像分区，结果页逐分区展示替换前后条数。下列任一情况整组保留原状并提示原因：

| 拒绝原因 | 判定 |
| --- | --- |
| 缺少对应的封账月 | 组内某分区在本地 `months` 中不存在，或存在但尚未封账（无封账流水可作替换源） |
| 预览过期（组内分区被替换） | 重算的载入代次 / 行数 / 内容指纹与预览快照不一致（含相同内容重传，代次也会变化） |
| 组外分区被错投连入 | 重算的连通分量成员与预览时不同，新增了组外分区 |
| 写入失败 | 事务内任何 SQL 异常，整体 `ROLLBACK`，预览保持可重试 |

已确认的预览不可重复执行；无关分区的上传与另建预览不影响已有预览，旧预览在未失效前仍可确认。
重装只改写数仓镜像三张表（`wh_partitions` / `wh_postings` / `wh_previews`），
本地封账账（`postings` 等）一行不动，封账触发器仍然有效。

勘误/封账先后两种顺序、幂等重放跨月、同号异内容拒绝、批中冲突整体回滚、
并发同号勘误只生效一次、触发器阻止写已封月与重开月份、导出内容；

预览过期（组内被替换、组外被连入）、写入失败整组回滚、预览不可重复确认。

## 已知限制

- 单机 SQLite（WAL）+ 单 worker 部署；多副本需换成服务端数据库或共享卷上的单写者。
- 没有登录/权限体系；请部署在内网或前置认证代理，并设置 `SECRET_KEY`。
- 封账不可逆（符合“封闭月明细保持原样”的要求）；如需更正已封月，只能在新月勘误。
- 勘误文件按整批原子处理，不做部分成功。
- `amount_cents` 允许负数（用于冲回）；原单导入阶段未禁止负金额，如业务上不允许可在解析处加约束。
